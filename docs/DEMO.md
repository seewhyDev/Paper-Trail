# 세미나 데모: LLM API Key가 에이전트가 되기까지

## 실행 전 준비

`python -m streamlit run app.py --server.port 8502`로 앱을 시작합니다. 모델을 실연하려면 서버 `.env`에 키를 설정하고 미리 `scripts/e2e.py`를 실행해 계정·모델·소스 가용성을 확인하세요. API 키나 `.env` 내용을 발표 화면에 띄우지 않습니다. 인터넷이 불안정하면 데모 모드를 사용하고 **합성 자료와 고정 스크립트**라고 먼저 알립니다.

## 7~9분 진행

| 시간 | 화면/동작 | 설명 |
|---|---|---|
| 0:00–1:00 | `examples/three_levels.py`의 direct/workflow/agent 분기 | API 키는 모델 접근 권한. 다음 행동의 제어권이 있어야 에이전트 루프가 됨 |
| 1:00–2:00 | 연구 질문 입력, 원하는 도움과 제약 입력 | 모델은 목표를 해석하고 프로그램은 실행 한도를 담당 |
| 2:00–4:00 | CLI로 내보낸 trace에서 요청·결과·다음 턴 연결 | `call_id`, 실제 검색 결과, 실패 관측을 확인. 내부 사고 과정은 출력하지 않음 |
| 4:00–5:00 | 후보 원문 열람 범위와 평가 이유 | 확보한 원문과 실제 읽은 구간은 다름; 초록만으로 원문 검토 완료라 하지 않음 |
| 5:00–6:30 | 추천 논문·출처와 인용, PDF | 주요 주장→근거 ID→절/페이지/quote 확인. 논문 주장과 해석 구분 |
| 6:30–8:00 | 합성 fulltext_failure 또는 mismatch | 모델 판단이 아닌 재현 가능한 plumbing 데모임을 표시. 오류 전달/후보 제외 경로 설명 |
| 8:00–9:00 | 검증 결과 문서, 실제 모델 평가 명령 | 고정 응답 테스트와 실제 모델 행동 평가, 실제 소스 E2E를 구분 |

실제 실행에서는 재검색·후보 교체를 강제로 연출하지 않습니다. 처음 확보한 근거가 충분해 종료하는 것도 정상입니다. 실행 시간이 길면 모델 호출을 무한히 기다리지 않고 저장된 trace/PDF를 보여 주며 **이전 실행 기록**임을 밝힙니다.

UI는 연구자용으로 정리되어 원시 실행 기록을 표시하지 않습니다. 세미나에서 에이전트 루프를 설명할 때는 CLI의 `--export`로 내보낸 trace를 별도로 여세요. 합성 실패/불일치 시나리오는 CLI의 `--scenario`로 실행합니다.

## 합성 시나리오

| 이름 | 도구 관측 | 고정 데모가 보여 주는 경로 |
|---|---|---|
| sufficient | 3개의 적합한 합성 원문 | 근거 기록 후 조기 완료 |
| insufficient | 첫 검색 결과 0개 | 질의를 변경하고 다시 검색 |
| fulltext_failure | 첫 후보의 기본 원문 경로 실패 | PDF 경로 선택 |
| mismatch | 한 원문은 라벨 100만 개 조건 | 적은 라벨 조건과 불일치해 제외, 다른 후보 유지 |
| budget | 도구 예산 2회 | 불완전 종료, 미검토 후보를 최종 추천하지 않음 |

이 표는 **ReplayProvider의 스크립트**를 설명합니다. 같은 FixtureSources를 실제 OpenAIProvider와 연결하는 평가 경로가 별도로 있습니다. 실제 모델의 선택은 이 표와 완전히 같은 도구 순서일 필요가 없습니다.

## 서로 다른 분야의 실제 모드 입력 예시

### 컴퓨터과학

연구 질문: “라벨이 적은 한국어 문서 분류를 연구하려고 합니다. 대형 모델 전체를 재학습하지 않고 사용할 수 있는 방법을 비교해 주세요.”

원하는 도움: “실험 기준선으로 사용할 서로 다른 접근을 약 3편 선정하고 먼저 읽을 절을 알려 주세요.”

제약: “공개 원문, 계산 자원 제한. 언어·데이터셋·라벨 수가 다른 실험 수치는 직접 순위로 비교하지 말아 주세요.”

### 생명과학

연구 질문: “단일 세포 CRISPR 스크리닝에서 perturbation 효과와 측정 잡음을 구별하는 분석 방법을 알아보고 싶습니다.”

원하는 도움: “방법 가정, 평가 데이터, 한계를 중심으로 시작 논문을 선정해 주세요.”

제약: “공개 원문, 치료 권고가 아니라 연구 방법 비교.”

### 재료·에너지

연구 질문: “리튬 이온 배터리의 소량 실험 데이터로 수명을 예측하는 연구를 시작합니다. 불확실성 추정과 도메인 이동을 다룬 방법을 비교해 주세요.”

원하는 도움: “재현 가능성, 검증 설계, 데이터 누수 위험이 드러나는 절 안내.”

제약: “셀 화학 조성과 실험 프로토콜이 다르면 성능을 동일 조건처럼 비교하지 않기.”

### 교육학

연구 질문: “대학 수업에서 형성평가 피드백의 학습 효과를 검토하고 싶습니다. 개입 설계와 측정 방식이 다른 연구를 비교해 주세요.”

원하는 도움: “연구 설계의 차이와 적용 시 주의할 조건.”

제약: “유료 원문 접근 우회 금지. 확보하지 못하면 참고 후보로 남기기.”

교육학처럼 Crossref로 후보를 찾더라도 지원 저장소에서 원문을 확보하지 못할 수 있습니다. 이때 추천 수를 채우지 않고 부족한 범위와 이유를 알리는 동작을 보여 줍니다. 예시 문구들은 입력 예시이며 해당 질문의 실제 모델 결과를 사전에 검증했다는 뜻은 아닙니다.
